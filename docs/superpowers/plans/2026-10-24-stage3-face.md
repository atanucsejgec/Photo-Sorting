# Stage 3: Face Mode Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add **Face** mode. The owner names the people in one photo, or ticks people the app already remembers. The app finds those people in every photo of the picked folder, asks about the unsure matches one at a time, and moves the photos into `<Name>/` folders, or `<Name1> & <Name2>/` when several named people are in a photo. This goes through the existing summary, Go and Undo flow.

**Architecture:**
- **AI runtime:** a thin layer (`ai/runtime.py`, `ai/models.py`) owns ONNX Runtime sessions (GPU first, CPU fallback) and model files (download with progress, SHA-256 check).
- **Faces:** `faces.py` turns a photo into a list of faces, each with a box, 5 landmarks, a score and a 512-number ArcFace embedding. It uses SCRFD detection plus ArcFace recognition from InsightFace `buffalo_l`, written in numpy, with no InsightFace/OpenCV package.
- **Cache:** results are cached in `.photosort/cache.db` (SQLite). The duplicates and repeated-shots measurements use the same cache.
- **People:** remembered people live in the app's data folder (`people.py`).
- **Face mode:** `modes/face_mode.py` matches faces to the ticked people and produces sure moves plus unsure questions. `plan_faces` turns the answers into an ordinary `Plan`.
- **UI:** the UI gains a Face setup page (people list, add person, naming faces) and a question page.

**Tech Stack:** Stage 2 stack, plus `onnxruntime-gpu` 1.31.0. The CUDA/cuDNN runtime comes through its `[cuda,cudnn]` extra, in a `gpu` dependency group. No OpenCV and no PyTorch. Everything is already in the local uv cache, and both models are already in `~/.local/share/photo-sorter/models/buffalo_l/`, so no download is needed on this laptop.

**Spec:** `docs/design.md` §5.2 (Face), with §2, §3, §4 (Cache), §6, §8 and §9. The earlier plans are `2026-10-24-stage1-core-date.md` and `2026-10-24-stage2-duplicates-repeated.md`.

**Measured by the controller before planning** (40 photos from the test copy):
- **Speed:** 176 ms per photo on the RTX 3050 Ti and 371 ms per photo on the CPU, with 1600 px decode and 640 px detection.
- **Similarity:** the same person scores about 0.80–0.95, and different people score about 0.09–0.25.
- **Detector:** SCRFD outputs come as 9 tensors, ordered (scores ×3, boxes ×3, landmarks ×3) for strides 8/16/32 with 2 anchors per cell. The input is `input.1`, shape `[1,3,H,W]`.
- **Recognizer:** the input is `input.1`, shape `[N,3,112,112]`, and the output is `[N,512]`.

## Global Constraints

- **Earlier rules still hold.** Everything in stage 1 and stage 2's Global Constraints still applies:
  - never delete, never overwrite, journal before every move;
  - relative POSIX paths, case-insensitive names, Windows-valid names, no symlinks;
  - subfolders off by default, nothing moves before Go;
  - copies only during development;
  - all tunables live in `photosort/thresholds.py`.
- **Photos and face data never leave the machine.** The only network use is downloading the model files from the URLs in `ai/models.py`, and only when a model file is missing.
- **Model files** live in `platformdirs.user_data_dir("photo-sorter")/models/`. The two buffalo_l files are:
  - `buffalo_l/detection/model.onnx`: 16,923,827 bytes, sha256 `5838f7fe053675b1c7a08b633df49e7af5495cee0493c7dcf6697200b85b5b91`, from `https://huggingface.co/immich-app/buffalo_l/resolve/main/detection/model.onnx`.
  - `buffalo_l/recognition/model.onnx`: 174,383,860 bytes, sha256 `4c06341c33c2ca1f86781dab0e829f88ad5b64be9fba56e56bc9ebdefc619e43`, from `https://huggingface.co/immich-app/buffalo_l/resolve/main/recognition/model.onnx`.
- **GPU:** the GPU is used when Settings "Use GPU" is on and CUDA works. Otherwise the app uses the CPU, silently for the run, and Settings shows which one is in use. ONNX Runtime's own console logging is set to errors only.
- **Videos are skipped** in Face mode (§4 "Files handled").
- **Remembered people** are stored in `user_data_dir/people/`, never inside the sorted folder. Names are cleaned with `naming.safe_name`, and names are unique case-insensitively.
- **Where photos go:**
  - One named person: `<Name>/<basename>`.
  - Two or more named people: `<A> & <B>/<basename>`, names sorted case-insensitively.
  - None of the named people: the photo stays put.
  - Strangers are ignored. A photo with one named person and three strangers goes to `<Name>/`.
- **Sure and unsure:**
  - Similarity ≥ `FACE_SURE` (0.45) is sure.
  - `FACE_UNSURE` (0.30) ≤ similarity < `FACE_SURE` is unsure, and is asked about before anything moves.
  - Below `FACE_UNSURE` is a stranger.
  - Each named person matches at most one face per photo, and each face matches at most one person. Greedy assignment, highest similarity first.
- **Asking about unsure matches:**
  - **Yes** adds that person to the photo.
  - **No** removes them.
  - **Skip** leaves the whole photo where it is.
  - The confidence shown is `confidence_percent(similarity)`, a linear map of `[FACE_UNSURE, FACE_SURE]` onto 30–90 %, clamped to 1–99 **(my call)**.
- **Matches don't change remembered people.** Recognition is improved only by "Add photos" on a person **(my call: avoids drift)**.

## Review Focus

1. **A folder already sorted by face, rerun with subfolders on.** A photo already in `Atanu/` that matches only Atanu must stay in place, counted as unchanged, not moved to `Atanu/Atanu (1).jpg`. Test in Task 4.
2. **No usable GPU** (CUDA libraries missing, or "Use GPU" off). Face mode must still work on the CPU, and Settings must say "CPU". Test in Task 1 (providers fallback and the CPU retry in `make_session`).
3. **A model file is missing or corrupt** (for example on a fresh clone, or after an interrupted download). The app downloads it with progress. A checksum mismatch never leaves a file that is then trusted, and Cancel leaves no half file under the real name. Test in Task 1.
4. **A photo with no faces, a tiny background face, a sideways photo (EXIF orientation 6), or an unreadable file.** None of these may crash the run. Unreadable files are counted and stay put. Orientation is applied before detection. Test in Task 2 (orientation applied, unreadable photo) and Task 4 (no faces, unreadable counted).
5. **A person name the owner types with a slash, a trailing dot, or a different case of an existing name.** It is cleaned with `safe_name`, and a duplicate name is refused with a message. Test in Task 3 and Task 5.

### Task 2: Face detection and embeddings

**Files:**
- Create: `src/photosort/faces.py`, `tests/test_faces.py`
- Modify: `src/photosort/thresholds.py`

**Interfaces:**
- Consumes: `runtime.make_session`, `models.model_path`, `imageinfo.UnreadableImage`, and the decoding rules from `imageinfo` (draft, then EXIF transpose, then RGB).
- Produces:
  - Thresholds:
    - `FACE_SURE = 0.45`, `FACE_UNSURE = 0.30`
    - `FACE_DET_SCORE = 0.5`, `FACE_NMS_IOU = 0.4`
    - `FACE_DET_SIZE = 640`, `FACE_DECODE_PX = 1600`
    - `FACE_MIN_PX = 24`: the shortest box side, in decoded pixels, below which a face is ignored.
  - `Face(box: tuple[float, float, float, float], landmarks: np.ndarray (5,2), score: float, embedding: np.ndarray (512,) float32, unit length)`. Coordinates are in the decoded, upright image's pixels, and `Face` carries `image_size: tuple[int, int]` so that boxes can be scaled.
  - `decode_scrfd(outputs: list[np.ndarray], scale: float, det_size: int) -> tuple[boxes (n,4), landmarks (n,5,2), scores (n,)]`:
    - It is pure numpy. Anchor centres are `(x, y) * stride` on an `(det_size/stride)²` grid, repeated twice for the 2 anchors.
    - Box = centre ∓ distance·stride, and landmarks = centre + offset·stride.
    - It keeps scores ≥ `FACE_DET_SCORE`, applies NMS at `FACE_NMS_IOU`, then divides by `scale`.
  - `align(img: Image.Image, landmarks: np.ndarray) -> Image.Image`:
    - It returns a 112×112 crop.
    - It uses an Umeyama similarity transform from the 5 landmarks onto the ArcFace template `[[38.2946,51.6963],[73.5318,51.5014],[56.0252,71.7366],[41.5493,92.3655],[70.7299,92.2041]]`.
    - The warp is applied with `Image.transform(AFFINE)` using the inverse matrix.
  - `FaceEngine(use_gpu: bool)`:
    - It lazily creates the two sessions.
    - `.detect(img) -> list[(box, landmarks, score)]`: the image is letterboxed top-left onto a 640² canvas, normalised `(x-127.5)/128`, RGB, CHW.
    - `.embed(img, landmarks) -> np.ndarray`: normalised `(x-127.5)/127.5`, RGB, then L2-normalised.
    - `.analyse(path: Path) -> list[Face]`: it raises `UnreadableImage`, and embeds all faces of a photo in one batch.
  - `similarity(a, b) -> float`: the dot product of unit vectors.
  - `face_crop(path: Path, box, size: int = 160) -> Image.Image`: a square crop with a 30 % margin, clamped to the image, for showing in the UI.

**Interfaces:**
- Produces:
  - `AnalysisCache(root: Path)`. It is a context manager, opened on the worker thread that uses it.
    - The database is SQLite at `root/.photosort/cache.db`.
    - The table is `entries(kind TEXT, name TEXT, size INT, mtime_ns INT, data BLOB, PRIMARY KEY(kind, name, size, mtime_ns))`. `name` is the casefolded basename, so a hit survives the file being moved inside the folder.
    - `.get(kind, path) -> bytes | None` and `.put(kind, path, data: bytes)`.
    - It commits every 200 puts and on exit.
    - A corrupt or unopenable database is renamed to `cache.db.broken-<n>`, and a fresh one is used. The cache never stops a run.
    - The `kind` strings are `"photo-v1"` (the measure_photo tuple) and `"faces-v1"` (the face list).
    - Data is packed with `struct` / `numpy.tobytes`, never pickle.

  - `Person(id: str, name: str, embeddings: np.ndarray (k,512), thumb: Path)`.
  - `PeopleStore(folder: Path | None = None)`, with a default of `user_data_dir/people/`:
    - Storage is `people.json` (id, name, thumb file) plus `<id>.npy` and `<id>.jpg`. Writes are atomic (tmp + `os.replace`).
    - `.people() -> list[Person]`, sorted by casefolded name.
    - `.add(name, embedding, thumb: Image) -> Person`. It cleans the name with `safe_name`. It raises `PeopleError("A person called {name} already exists.")` for a case-insensitive duplicate, and `PeopleError("Type a name.")` for an empty name.
    - `.add_samples(person_id, embeddings)`.
    - `.delete(person_id)`.
    - `.best_match(embedding, person_ids) -> tuple[str, float] | None`: a person's score is the max similarity over their samples.

### Task 4: Face mode logic

**Files:**
- Create: `src/photosort/modes/face_mode.py`, `tests/test_face_mode.py`

**Interfaces:**
- Consumes: `scan`, `kind`, `AnalysisCache`, `FaceEngine.analyse`, `PeopleStore.best_match`, `TargetAllocator`, `resolve_existing_dir`, `Plan`/`Move`.
- Produces:
  - `Question(rel: str, person_id: str, name: str, box, image_size, similarity: float, percent: int)`.
  - `FaceScan(sure: dict[str, set[str]], questions: list[Question], photos: int, unreadable: int)`. `sure` maps rel → person ids.
  - `find_face_matches(root, include_subfolders, people: list[Person], analyse: Callable[[Path], list[Face]], progress=None, cancel=None, cache=None) -> FaceScan | None`:
    - Photos only. Assignment is greedy, by similarity, one-to-one.
    - Faces under `FACE_UNSURE` are ignored. A photo whose matches are all sure goes straight into `sure`.
    - Every unsure match becomes a Question. A photo can have sure persons **and** questions.
    - Questions are ordered by rel, then by name.
  - `confidence_percent(similarity) -> int`.
  - `together_folder(names: Iterable[str]) -> str`: `" & ".join(sorted(names, key=str.casefold))`.
  - `plan_faces(root, scan, people, answers: dict[tuple[str, str], Literal["yes", "no", "skip"]]) -> Plan`:
    - A photo with any `"skip"` answer stays put, and so does a photo with an unanswered question.
    - Otherwise its names are its sure persons plus its "yes" persons.
    - No names → it stays put.
    - Target is `resolve_existing_dir` of the folder + basename, allocated with `TargetAllocator`.
    - A photo already directly inside its target folder (casefolded) is counted unchanged, not moved.
    - `Plan.mode` is `"face"`.
    - Summary lines:
      - `"{n} photos → {p} person folders, {t} together folders"`
      - `"{s} photos stay where they are"`
      - `"{u} photos couldn't be read"`, only when u > 0.
- Also add `"face"` to `MODES` as available, and add `MODE_SPECS["face"] = ModeSpec("face", …)`. The main window wiring comes in Task 6.
